# 海狸IM 2.1 梳理：桌面端、移动端与后台的产品结构及技术栈

即时通讯软件我们每天都在用，但把它当作一个需要长期维护的系统来看，涉及的事情远不止一个「聊天窗口」。

有人用电脑处理消息，有人用手机在路上回复，还有一类角色（管理员或运维）需要在后台掌握运行状态——谁在线、版本发到哪了、有没有异常消息、依赖服务是不是都正常。海狸IM 用一套开源、可私有化部署的产品覆盖这几类场景。

它基于 MIT 协议开源，后端是 Go + Go-Zero 微服务，前端覆盖桌面端、移动端和管理后台，另有独立的开放平台与 OAuth 授权页。这篇不逐个端展开逐功能（那部分另有专文），而是先建立一张「全景图」：这套产品由哪几块拼成、各自负责什么、技术选型是怎样的。

## 一、为什么是「多端一体」，而不是一个 App

不少 IM 只有手机版或只有桌面版，结果是消息分散在不同入口，后台治理能力也往往缺失。

海狸IM 的结构是一个后端、一套账号、多端同步：

- 桌面端是主力办公入口，功能最全；
- 移动端承接通勤和外出时的沟通；
- 管理后台不聊天，专门负责治理——用户、版本、审计、监控；
- 开放平台 / OAuth 让第三方应用接入，使用统一账号登录。

四个部分共享同一套账号体系，消息、好友、群、朋友圈、圈子实时同步——你在电脑上点开过的会话，手机上的红点也会同步消除，反之亦然。

| 端 | 技术 | 平台 | 定位 |
|----|------|------|------|
| 桌面端 | Electron + Vue 3 | Windows / macOS / Linux | 主力办公端，功能最全 |
| 移动端 | Flutter | Android / iOS | 手机端延伸，通勤 / 外出使用 |
| 管理后台 | Vue 3 + Element Plus | 浏览器 | 运营管理、用户治理 |
| 开放平台 / OAuth | beaver-open / beaver-oauth | 浏览器 | 第三方应用接入、授权登录 |

## 二、桌面端：主力办公入口

桌面端基于 Electron + Vue 3，一套代码跑在 Windows、macOS、Linux 上。它是四个端里功能最完整的一个，也是大多数人在工位上的默认入口。

登录方式有三种：密码、扫码，以及通过开放平台的 OAuth 授权码登录 + 移动端扫码确认——最后一种适合接入企业内部系统时，用统一账号完成登录。

![桌面端登录](https://i-blog.csdnimg.cn/direct/3229c1fc62ee4677af072ce113afe407.png)

聊天部分，除了发送文字，还支持引用回复、合并转发、Markdown（代码与表格）、语音消息和表情商店。对研发和运营场景来说，这些细节直接影响日常沟通效率。

![桌面端消息主界面](https://i-blog.csdnimg.cn/direct/ec0198547eb94c0cb24806a41818ea5f.png)

桌面端也包含社交类功能。朋友圈用于发状态、查看动态、点赞评论，红点实时同步；圈子更接近一个内部社区 / 兴趣组——建组、发帖、用二维码或名片拉人，适合沉淀话题和资料，区别于以会话流为主的普通聊天。

![朋友圈主页](https://i-blog.csdnimg.cn/direct/787fa2c5ae82444f9f0f9798aeabcd89.png)

![圈子模块](https://i-blog.csdnimg.cn/direct/7637fc896c7e438091f06ab18804d76f.png)

还有一块常被忽略但实用的能力：工作台。它本质上是一个应用中心，可以把内部 OA、工单系统这类 Web 应用嵌进来，用统一的 OAuth 账号登录——相当于把多个内部系统收口到一个入口，减少在不同页面间切换。

## 三、移动端：手机端延伸

移动端用 Flutter 一套代码覆盖 Android 和 iOS。对开源项目而言，单套跨端工程有利于降低长期维护成本：一次更新，两端同步。

它的能力与桌面端对齐：登录（含手机特有的「找回密码」）、聊天（消息 / 语音 / Markdown / 图片 / 私聊设置 / 表情商店）、好友（列表 / 新的朋友 / 详情 / 添加 / 搜索 / 扫码）、群（发起 / 列表 / 设置）、朋友圈（看动态 / 点赞 / 评论），圈子和工作台同样在移动端实现，数据互通。

![移动端登录](https://i-blog.csdnimg.cn/direct/b7a9c252987f4b40b9b2c54187345f1e.jpeg)

![移动端消息](https://i-blog.csdnimg.cn/direct/9c420b29a6974d8dbd7565ee695b2765.jpeg)

移动端有两个桌面端没有、却更顺手的入口：「我的二维码」用于线下交换联系方式，「扫码」用于加好友、进群，比在桌面端通过图片识别二维码更顺手。出差、开会、通勤时，这类界面承担了大量即时操作。

![移动端我的二维码](https://i-blog.csdnimg.cn/direct/65b487b7c2d24c22b24201f081ccba31.jpeg)

## 四、管理后台：治理层

如果说桌面端和移动端是「用」的人看的，那管理后台就是「管」的人看的。它基于 Vue 3 + Element Plus，跑在浏览器里，不聊天，只负责治理。

运营工作台是一眼总览：用户情况、在线连接、待办事项。往下展开，才是它实际承担的职责：

- 用户 360 视图：一个用户的资料、好友申请、所在群、相关会话，集中在一页查看；
- 版本发布管理：灰度推送新版本，而非全员一刀切；
- 消息 / 会话审计：出现问题可回溯记录，适用于合规场景；
- 资源管理：文件存储、表情包等内容资产的统一管理；
- 开放平台：开发者配置、应用、集成、Webhook；
- 连接监控：掌握各依赖服务运行状态。

![管理后台运营工作台](https://i-blog.csdnimg.cn/direct/adac0282ef0c44098c0bb6a7676c81a8.png)

对私有化部署的场景来说，这一层与聊天功能本身同样重要——「可管、可查、可控」是这类系统落地的常见诉求。

## 五、能力矩阵：各端差异

把三端能力摊开对比，可以更清楚哪些事在哪一端完成：

| 能力模块 | 桌面端 | 移动端 | 管理后台 |
|----------|--------|--------|----------|
| 登录 / 账号 | ✓（密码 / 扫码 / OAuth+扫码确认 / 多端设备） | ✓（含找回密码 / OAuth 扫码确认） | ✓（管理员） |
| 私聊 / 群聊 | ✓ | ✓ | — |
| 音视频通话 | ✓（LiveKit） | ✓ | — |
| 朋友圈 | ✓ | ✓（看 / 评） | — |
| 圈子 | ✓（创建 / 发帖 / 分享 / 二维码） | ✓（看 / 扫码加入） | — |
| 工作台（嵌入应用） | ✓ | ✓ | — |
| 好友 / 群组管理 | ✓ | ✓ | ✓（用户 / 群治理） |
| 运营管理 | — | — | ✓（用户 360 / 版本 / 日志 / 资源 / 开放 / 监控） |

「—」表示该端不提供此能力。聊天、音视频、朋友圈、圈子是面向用户的通信 / 社交能力，集中在桌面端与移动端；运营管理是后台专属，普通用户无需接触。

## 六、技术栈

后端是 Go + Go-Zero 微服务架构，按业务拆成十余个独立服务（user / auth / chat / ws / group / file / moment / system …），每个服务预留独立端口，便于多实例水平扩展。完整选型如下：

| 层 | 技术 | 说明 |
|----|------|------|
| 语言 / 框架 | Go 1.24 + Go-Zero 1.7 | 微服务 API / RPC |
| 通信 | gRPC、WebSocket、RocketMQ | 服务间调用与实时消息推送 |
| 实时通信 | WebSocket | 长连接实时推送 |
| 音视频 | LiveKit | 私聊 / 群聊音视频通话 |
| 存储 | MySQL 8.0、Redis 6.0 | 多库拆分 + 缓存会话 |
| 服务发现 | ETCD 3.5 | 服务注册与发现 |
| 消息队列 | RocketMQ | 异步解耦、消息投递 |
| 基础设施 | Docker | 一键编排部署 |
| 桌面端 | Electron + Vue 3 | 跨平台桌面客户端 |
| 移动端 | Flutter | Android / iOS 跨端 |
| 管理后台 | Vue 3 + Element Plus | 运营管理后台 |
| 开放平台 / OAuth | beaver-open / beaver-oauth | 应用配置、授权登录、Webhook |

技术栈取自 beaver-server 官方 README 与 go.mod / docker-compose.yml。

部署方面，项目支持私有化：一条 `docker-compose up` 即可拉起 MySQL / Redis / ETCD / LiveKit / RocketMQ 全套依赖，开箱即用。数据保存在自建服务器上，适合对数据驻留有要求的私有化场景。
