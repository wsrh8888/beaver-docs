# 海狸IM 2.1 上手一周：部署、日常使用与一些真实不足

> 关键词：开源 IM、私有化部署、上手记录、真实体感、LiveKit、圈子、工作台、OAuth 授权

先交个底：海狸IM 是我个人维护的开源即时通讯项目（部分工作由 AI 辅助完成），MIT 协议、可私有化部署。上篇《海狸IM 2.1 更新解读》讲了它有哪些能力和技术栈；这篇不重复那些，只记录我把它部署起来、当日常通讯工具用了一周的真实体感——包括顺手的地方，也包括目前还不够顺手的地方。

---

## 一、部署与第一天：docker-compose 一把梭，但有小坑

后端是一套 Go + Go-Zero 微服务，依赖 MySQL / Redis / ETCD / LiveKit / RocketMQ。官方给了 docker-compose，理想情况下一条命令拉起。我实际跑的时候，第一天卡在两件事上：一是宿主机已有 MySQL 占了 3306，得改映射端口；二是 LiveKit 的端口没放行，音视频一直连不上。对着 `docker-compose.yml` 调完就好了——对没接触过这套栈的人，第一天会有一点学习成本。

桌面端（Electron + Vue 3）装好之后，登录支持密码和扫码两种。扫码登录时手机端确认一下就完成跨端授权，这个流程比每次输密码省事。

## 二、把团队沟通搬进来：Markdown 是真香

以前群里讨论需求，接口文档要么截图要么甩文件。搬到海狸IM 之后，直接发 Markdown：代码高亮、表格都正常渲染，需求评审当场就能在消息里写完，不用再切到别的文档工具。这是我每天都用、且明显提升效率的一点。

## 三、开会不用再开别的软件

群聊里点一下就能发起音视频通话，底层是 LiveKit，桌面和手机互通。比起"先约会议软件、再发链接、再等人进"，在 IM 里聊着不顺直接开麦，心智负担低很多。实测同一局域网内延迟可接受，跨网络的稳定性取决于你部署 LiveKit 的带宽，这点下面"不足"里还会提。

## 四、圈子成了我们的团队知识库

朋友圈偏个人动态，圈子更适合沉淀内容。我把周报、踩坑记录、上线公告都发到对应圈子，比在群里刷屏然后被冲掉强太多——聊天一刷就过，圈子是按主题可回溯的。这一点是我用下来最超出预期的地方。

## 五、工作台把内部系统收口

工作台是桌面端内置的应用中心，能嵌入第三方 Web 应用。我把内部查数页面嵌了进去，点开即用；配合开放平台的 OAuth 应用配置，嵌进来的应用可以走统一授权登录，少记一套账号密码。对小团队把散落的 Web 工具收拢到一个入口，挺实用。

## 六、群助手让群不只是聊天

群助手（群通知机器人 / Webhook）能把外部系统的消息推到群里。我接了构建告警和监控通知，CI 一红群里立刻知道，不用再盯邮件或另开一个告警面板。开放平台已经留好机器人 + Webhook 的接口，接法不复杂。

## 七、一些真实的不足（不回避）

体感友好的部分上面写了，下面是我觉得目前还不够顺手、或需要你心里有数的地方：

- **部署门槛**：微服务 + 多依赖，对纯小白不友好。第一天的端口/防火墙小坑我有，新手大概率也会有。文档（beaver-docs）在持续补，但还没到"零基础十分钟跑通"的程度。
- **迭代节奏**：这是个人维护、AI 辅助的项目，更新频率和企业级 IM 不能比。新功能以官方更新公告为准，别期待商用产品那种排期。
- **移动端与桌面端对齐**：两端功能大体对齐，但少数边界场景（如某些通知细节、个别设置项）仍在持续补齐，跨端体验不是 100% 一致。
- **生态还在早期**：机器人 / Webhook / 第三方应用目前现成集成不多，好在经过开放平台接口能自己接。相比大厂开箱即用的集成市场，这里要自己动手。
- **音视频跨网络质量**：LiveKit 部署在你自己的环境，跨公网的延迟和稳定性取决于你的带宽与转发配置，需要按实际调。

这些都是"个人开源项目"的现实面，不是黑稿——恰恰因为代码开源、能私有化，上面的每一条你都能自己改、自己部署时规避。

## 八、技术栈一句话

后端 Go + Go-Zero、实时通信 WebSocket、音视频 LiveKit、存储 MySQL/Redis、服务发现 ETCD、消息队列 RocketMQ；桌面端 Electron + Vue 3，移动端 Flutter。完整选型表见上篇《海狸IM 2.1 更新解读》，本文不再重复。
