# 海狸IM 2.1 OAuth 授权码登录 + 移动端扫码确认：一次登录到底发生了什么

先说一件事：很多文章和评论区里有人把海狸IM 这套扫码登录叫做「auto2」。这是误称。代码里压根没有 `auto2` 这个词，它实际是标准的 **OAuth 2.0 授权码模式**（Authorization Code Flow），配合移动端 App 做授权确认。下面把整条链路拆开讲清楚。

## 一、你看到的入口

在桌面端打开 beaver-desktop，登录页是这样的：

![桌面端扫码登录](https://i-blog.csdnimg.cn/direct/5f82e082310a4966bc14d3142cd3f185.png)

界面上有两个 tab：**密码登录**和**扫码登录**。扫码登录走的就是 OAuth 授权码流程。

这一页其实是嵌了一个叫 `<beaver-login>` 的组件，它来自 `@beaver-im/js-sdk` 包（海狸官方的前端 SDK）。SDK 内部负责生成二维码、维护长连接、监听移动端确认事件，本身不存用户凭证。

## 二、一次完整的扫码登录，5 步走完

把一次成功的扫码登录展开，桌面端、beaver-oauth、手机 App、beaver-server 四个角色大致是这样配合的：

| 步骤 | 谁发起 | 动作 | 关键数据 |
|------|--------|------|----------|
| 1 | 桌面端 | 加载 `<beaver-login>` SDK，生成二维码 | 二维码内容（sceneId） |
| 2 | 手机 App | 扫桌面端的二维码，跳到 beaver-oauth | sceneId 透传 |
| 3 | 手机 App | 用户在手机上看到「确认登录 XX 设备」，点头 | 用户在海狸 App 内的账号态 |
| 4 | beaver-oauth | 把授权码 authCode 推送给桌面端 SDK | authCode 一次性、10 分钟过期 |
| 5 | 桌面端 | 用 authCode 调后端换 IM token | userId + token |

第 5 步在代码里就是这一个调用（位置在 `beaver-desktop/src/render/api/auth.ts`）：

- 方法：POST
- 路径：`/api/auth/auth_public/v1/oauth_code_login`
- 请求体：`{ oauthId: "海狸桌面端", code: "从 SDK 拿到的 authCode" }`
- 返回：`{ userId, token }`

拿到 token 后，桌面端用 `electron.storage.setAsync('userInfo', { userId, token }, { persist: true })` 持久化，然后进主界面。整个过程桌面端不接触用户的密码或手机验证码。

## 三、三个端各自在干嘛

把这套流程拆到工程上看，是四个项目协同：

| 工程 | 角色 | 关键文件 |
|------|------|----------|
| beaver-desktop | 桌面端登录入口，发起授权 | `src/render/windows/login/App.vue` + `src/render/api/auth.ts` |
| beaver-oauth | 独立授权页（用户看见的"同意授权"页），颁发 code | `src/pages/oauth/authorize.vue` |
| beaver-flutter | 移动端 App，负责扫码 + 在手机上点确认 | `lib/features/oauth/scan/scan_confirm.dart` |
| beaver-server | 颁发 IM token，登记登录设备 | `api/auth/auth_public/v1/oauth_code_login` |

容易混的是 beaver-oauth 和 beaver-desktop 登录页这两个长得像的页面：

- beaver-oauth 是一个**独立部署的 Web 应用**，域名通常是 `https://oauth.xxx`，给**第三方应用**用（跳转授权）。它的入口地址形如 `/oauth/authorize?oauthId=xxx&redirectUri=xxx&scope=user_info&state=xxx`。
- beaver-desktop 登录页是**桌面客户端内部嵌的 SDK**，给自己用（扫码登录）。底层流程其实一样，但终端不一样。

Flutter 端那个扫码确认页面（`OAuthScanConfirmPage`）拿到 `sceneId` 后会调 bloc 初始化，状态变 success 时弹个 toast 就完成了。它在手机这边只承担一个动作：点头确认。

## 四、第三方应用想接入，怎么走

如果你不是用海狸桌面端，而是想给自己的 Web 应用接一个「用海狸账号登录」按钮，走的是另一条标准 OAuth 流程，beaver-oauth 仓库的 OAUTH_README 写得很清楚，分 4 步：

1. 你的网站拼一个 URL，把用户重定向到授权页：

   `https://beaver-oauth.com/oauth/authorize?oauthId=xxx&redirectUri=xxx&scope=user_info&state=随机串`

2. 用户在授权页看到「XX 应用想访问你的账号：昵称、头像」，点同意。

3. 授权页回调你的 redirectUri，URL 上带 `?code=授权码&state=你之前那个随机串`。

4. 你的服务端用 `oauthId + appSecret + code` 调 `POST https://beaver-server/api/open/v1/oauth/token`，返回 access_token，再拿 token 拉用户信息。

要在 beaver-open 开放平台开个应用：创建应用 → 拿到 AppID/AppSecret → 配置回调域名和权限 Scope（默认 `user_info`）→ 上线。这一步在 2.1 版本里和旧版的差异不大，主要是接入了 v1 路由。

## 五、几个安全细节，知道就好

这部分是 beaver-oauth 文档明文写的，做接入的时候容易忽略：

- **code 一次性**：授权码只能用一次，10 分钟过期，过期要重新授权。
- **state 必须校验**：回调时第三方要校验 `state` 是不是当初发出去的那个随机串，不然有 CSRF 风险。
- **App Secret 不能放前端**：只能在自家服务端用，一旦泄漏别人就能冒充你的应用。
- **授权页必须在 Beaver 域名下**：beaver-oauth 自己部署在 Beaver 的子域里，是为了防止仿冒授权页钓鱼。
- **权限 Scope**：`user_info` 是默认的最小权限，要更多字段要在开放平台申请新 Scope 并过审核。

## 六、还没做的地方

照实说，这一套目前还是**早期版本**。beaver-oauth 自己的 README 里就列了「待完善」：

- 样式还没充分优化
- 错误处理比较粗
- 没做国际化
- 没有单元测试

也就是说，如果是生产环境的第三方接入，建议先用沙箱环境跑通、再考虑接入；权限 Scope 目前也只有 `user_info` 一种，想要拿更多用户字段得联系开放平台加。
